# 记忆体系架构（Memory Architecture）

> 建立：2026-09-30（董事长授权"自己规划"）
> 目的：解决"失忆/状态漂移/记忆污染"三类问题
> 原则：分层、可检索、可验证、防污染

---

## 一、分层设计（5层，按"重要性×时效"分）

```
┌─────────────────────────────────────────────┐
│  L4 · 宪法层（几乎不变）                      │
│  · 我是谁、原则、红线                         │
│  · 改=重大事件，需董事长确认                  │
│  · 文件：PRINCIPLES-LOCKED / IDENTITY-ANCHOR │
│         MY-STRATEGY / BEHAVIOR-LOCKED        │
├─────────────────────────────────────────────┤
│  L3 · 长期记忆（周/月级）                     │
│  · 决策、机制、团队、系统架构                  │
│  · 文件：decisions.md / mechanisms.md        │
│         TEAM-PRINCIPLES / MEMORY-ARCHITECTURE│
├─────────────────────────────────────────────┤
│  L2 · 待审区（临时，需审核）                  │
│  · 外部信息进来先到这里                        │
│  · 审核后才能升到 L3                          │
│  · 目录：memory-layers/quarantine/           │
├─────────────────────────────────────────────┤
│  L1 · 近期记忆（天级）                        │
│  · 今日进展、当日讨论、临时数据                │
│  · 目录：memory-layers/L1-recent/            │
│  · 7天后自动归档                              │
├─────────────────────────────────────────────┤
│  L0 · 工作记忆（小时级）                      │
│  · 当前任务状态、临时变量                      │
│  · 目录：memory-layers/L0-working/           │
│  · 24小时清空                                │
└─────────────────────────────────────────────┘
```

---

## 二、什么进哪一层（判定标准）

| 内容 | 层级 | 判定标准 |
|------|------|---------|
| 原则、身份、红线、战略 | **L4** | 改了会"变一个人" |
| 决策、机制、团队规则 | **L3** | 影响长期行为 |
| 外部信息（掘金内容/客户反馈） | **L2→审核→L3** | 必须先审核（第-2条） |
| 今日进展、讨论记录 | **L1** | 7天后归档 |
| 任务中间态、临时数据 | **L0** | 24小时清空 |

**关键规则：**
```
① 外部信息必须过 L2（待审区）—— 不许直接进 L3/L4
② L4 只能由"我+董事长"改 —— 团队不许碰
③ L1 自动降级到 archive —— 不许无限堆积
④ 每层必须有"索引"（不然找不到）
```

## 三、抗遗忘设计（双轨：文件 + 行为）

```
【文件轨】= 保"我是谁"
· L4 层文件
· 会话启动必读（BOOT.md 清单）

【行为轨】= 保"我怎么做事"（2026-09-30 新增）
· BEHAVIOR-LOCKED.txt
· behavior_audit.py（可检测漂移）
· 症状自检（问"要不要"/检讨/做执行活）

【为什么双轨】
只保文件 → "知道但做不到"（今天的教训）
只保行为 → 不知道"为什么这么做"
→ 必须双轨
```

## 四、防污染设计（第-2条落地）

```
【数据流】
外部信息 → 小子智能体（提炼） → L2待审区 → 我审核 → L3/L4

【禁止】
❌ 外部原始信息直接进 L3/L4
❌ 团队输出直接当事实
❌ 学习脚本写 L4 目录

【校验】
· 每条 L2 内容必须带 source + confidence
· 我审核时标注：收 / 退 / 参考
· 收进来的必须写"我们怎么用"
```

---

## 五、检索设计（怎么快速找到）

```
【按需检索】
· 问"我是谁" → L4（IDENTITY-ANCHOR）
· 问"为什么这么定" → L3（decisions.md）
· 问"最近干了什么" → L1（TODAY-*.md）
· 问"外部学了什么" → L2→L3（team-shared-memory）

【索引】
· MEMORY-INDEX.md（总索引，自动生成）
· 每个 L1 文件带日期前缀
· L3 用 topic 标签
```
